## 3 Подключение к общему Prometheus

Откройте http://93.88.178.186:9198/targets или Status → Targets. Найдите target93.88.178.186:5413. Он должен иметь состояние UP.

Если такого target нет, его нужно добавить в действующую конфигурацию Prometheus. Это делает преподаватель или тот, у кого есть доступ к конфигурационному файлу общего сервера. Файл prometheus/prometheus.yml из архива — готовый фрагмент для добавления внутрь существующего списка scrape_configs. Он не является полной конфигурацией и не должен заменять общий файл с настройками остальных студентов.

В существующем scrape_configs добавляется элемент:

```yaml
- job_name: web-metrics-nizovtsev13
  metrics_path: /metrics
  scrape_interval: 10s
  static_configs:
    - targets:
        - 93.88.178.186:5413
```

После применения конфигурации дождитесь опроса и проверьте в окне запросов Prometheus:

```promql
up{instance="93.88.178.186:5413"}
```

Ожидается 1. Затем проверьте:

```promql
http_server_request_duration_seconds_count{instance="93.88.178.186:5413"}
```

Prometheus сам читает /metrics калькулятора. Добавление адреса 9198 в Grafana не добавляет новый target в Prometheus. Если target уже есть под другим именем job, второй создавать не требуется: дашборд использует фильтр instance.

## 5 Дашборд и оповещение

Импортируйте grafana/calculator13-dashboard.json, выбирая источник ОБЩЕГО Prometheus. После того как target UP и запрос метрик возвращает данные, переходите к следующим шагам.

## 6 Три панели из пункта 3.7

В архиве подготовлен дашборд с тремя запросами из пособия:

1. В Grafana откройте Dashboards → New → Import.
2. Нажмите Upload dashboard JSON file и выберите файл grafana/calculator13-dashboard.json из распакованного архива.
3. В поле источника Prometheus выберите **Prometheus-13**.
4. Нажмите Import.
5. Откроется дашборд **Калькулятор Низовцев 13**: «Среднее время выполнения», «Количество запросов», «Ошибки».
6. Установите период Last1hour и обновление 10s. Выполните ещё несколько расчётов, подождите 20–30 секунд.
7. Поочерёдно откройте каждую панель → Edit → Queries → Code. Там виден её PromQL-запрос. Это окна, которые нужны для отчёта.

Если панели создаются вручную: New dashboard → Add visualization → Prometheus-13 → Time series; название и запрос скопируйте из grafana/queries.txt. Для времени установите Unit Seconds(s). Затем Save dashboard.

В запросах сохраняется фильтрация маршрутов из пособия и добавлен фильтр instance="93.88.178.186:5413". Он выделяет этот калькулятор независимо от имени job в общем Prometheus. Панель «Количество запросов» использует формулу rate(...[1h])*3600 из методички: это интенсивность, пересчитанная на час, поэтому значения могут быть дробными. «Среднее время выполнения» — формула avg_over_time(sum)/avg_over_time(count) из п. 3.7. Для «Ошибок» используется increase счётчика ответов 500 за 10 минут.

## 7 Проверка панели Ошибки

Интервалы ожидания ниже рассчитаны на scrape_interval 10s из фрагмента. Если уже подключённая общая цель опрашивается реже, ждите дольше её интервала.

В учебной версии обработчик деления на ноль возвращает HTTP500 с сообщением на форме. Это сделано для проверки указанной в пособии метрики ошибок; обычные расчёты работают как прежде.

1. В калькуляторе выберите деление, введите 1 и 0, нажмите «Рассчитать». Появится сообщение о невозможности деления на ноль.
2. Подождите 15 секунд, чтобы Prometheus получил начальное значение серии ответов 500.
3. Ещё раз выполните деление на ноль, подождите 15 секунд.
4. Обновите Grafana: на панели «Ошибки» должен появиться рост.

До возникновения HTTP500 эта панель может показывать No data: серии ошибок ещё нет. Первое событие новой серии становится исходной точкой для increase; для заметного прироста нужны события после первой выборки.

## 8 Оповещение о высоком времени выполнения

Оповещения входят в критерии оценки работы. Создайте правило в Grafana:

1. Откройте Alerting → Alert rules → New alert rule.
2. Имя: **Calculator13HighResponseTime**.
3. Выберите источник **Prometheus-13**. В запрос A вставьте запрос панели «Среднее время выполнения» из grafana/queries.txt. Диапазон запроса можно оставить Last5minutes: сама формула содержит окно[1h].
4. В Advanced / Expressions добавьте B типа **Reduce**, Input A, Function **Last**.
5. Добавьте C типа **Threshold**, Input B, **Is above0.5**. Сделайте C условием срабатывания (Set as alert condition).
6. Выберите или создайте Folder **Nizovtsev13**, Evaluation group **calculator13**, интервал проверки **30s**.
7. Pending period: **1m**.
8. Summary: «Среднее время выполнения калькулятора превышает 0.5 секунды».
9. Сохраните правило. В некоторых версиях интерфейса выбор Reduce и Threshold объединён в настройку условия; смысл тот же — последнее значение больше 0.5 в течение 1 минуты.

Для проверки состояния правила сначала выполните расчёты и убедитесь, что A возвращает данные. Временно замените порог 0.5 на 0, сохраните и подождите 1–2 минуты. При положительном времени выполнения появится Pending, затем Alerting / Firing. Сделайте скриншот и верните порог **0.5**, сохраните.

Так проверяется вычисление условия и срабатывание правила в интерфейсе. Для отправки уведомления на реальную почту нужен настроенный SMTP и контакт получателя; этих данных в задании нет. Если преподаватель выдаст канал, настройте его в Alerting → Contact points и выберите для правила. Не считайте запись Firing подтверждением доставки письма.
