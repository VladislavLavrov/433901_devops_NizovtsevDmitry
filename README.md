## 6. Автоматическая сборка после изменения кода

В той же задаче откройте Build Triggers / Триггеры сборки:

1. Включите Poll SCM / Опрос SCM.
2. В поле Schedule / Расписание укажите:

```text
* * * * *
```

3. Для этой схемы достаточно Poll SCM. Build periodically включать не нужно.
4. Нажмите Save / Сохранить.

Это настройка из раздела2.5 пособия: Jenkins проверяет репозиторий каждую минуту и запускает сборку при обнаружении нового коммита. Дополнительный GitHub webhook для такой настройки не нужен.

## 7. Первая сборка

1. В вашей задаче Jenkins нажмите Build Now / Собрать сейчас.
2. В Build History / История сборок нажмите номер начавшейся сборки.
3. Откройте Console Output / Вывод консоли.
4. Дождитесь Finished: SUCCESS. Должны завершиться три этапа: Hello, Build Docker Image, Start Docker Container.
5. Откройте http://93.88.178.186:5213/.
6. Проверьте8+2=10,9-4=5,6*7=42,12/3=4.
7. Сделайте скриншот исходной версии: кнопка «Рассчитать», виден результат и подпись студента.
8. Сохраните полный Console Output первой сборки для отчёта.

Если сборка завершилась FAILURE, нужен Console Output именно этой сборки. Если видите docker: not found или отказ в доступе к Docker, среду агента Jenkins должен настроить преподаватель; методический Jenkinsfile предполагает уже работающие docker compose и доступ к Docker. Не меняйте права общего сервера наугад.

## 8. Что делает код

- Controllers/CalculatorController.cs: GET показывает форму, POST принимает числа и операцию, вызывает CalculatorLibrary и выводит результат.
- Models/CalculatorLibrary.cs: четыре арифметические операции.
- Data/DataInputVariant.cs: объект исходных данных для расчёта из примера приложения5; это не база данных.
- Views/Calculator/Index.cshtml: форма и результат.
- Views/Shared/_Layout.cshtml: ФИО и группа.
- appsettings.json: прослушивание5013.
- Dockerfile: восстановление зависимостей, сборка и публикация.NET8 в образ.
- docker-compose.yml: сборка изCalculator/ и публикация5213:5013.
- Jenkinsfile: этапы вывода сообщения, docker compose build и docker compose up -d.

## 9. Изменение приложения и новая сборка

После успешной первой сборки и скриншота измените на КОМПЬЮТЕРЕ файл Calculator/Views/Calculator/Index.cshtml.

Было:

```html
<input type="submit" value="Рассчитать" />
```

Сделайте:

```html
<input type="submit" value="Вычислить результат" />
```

Именно изменение названия кнопки приведено в этапе9 пособия как пример новой функциональности.

Сохраните файл. В GitHub Desktop в ветке Jenkins сделайте Commit с сообщением «Change calculator button text» и Push origin. Одного локального коммита недостаточно: Jenkins должен получить новый коммит с GitHub.

Для проверки автоматизации не нажимайте Build Now сразу после Push: дождитесь ближайшего опроса (около минуты, плюс возможная очередь Jenkins). В истории должна появиться новая сборка. Проверьте её Console Output: причиной должен быть SCM change, завершение Finished: SUCCESS, в собранной ревизии должен быть ваш новый коммит.

Обновите калькулятор Ctrl+F5 на том же адресе5213. Кнопка должна называться «Вычислить результат». Выполните расчёт и сделайте скриншот. Сохраните Console Output новой сборки. Если преподаватель требует отдельный ручной запуск этапа9, после автоматической сборки можно также нажать Build Now.
