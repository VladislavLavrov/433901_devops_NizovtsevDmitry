Студент №13: Низовцев Дмитрий Алексеевич, НМТ-433901. Приложение ASP.NET Core MVC (.NET 8) сохраняет успешные расчёты в MariaDB. Основа: п. 1.7.2 пособия, с. 36–41 и приложение 3, с. 112–117.

## Что подготовлено

- Web и MariaDB в `docker-compose.yml`; отдельная сеть Compose и том для данных.
- EF Core 8.0.14 и Pomelo 8.0.3, как в пособии.
- База `13-WebCalculatorDb`, таблица `DataInputVariants`, поля `ID_DataInputVariant`, `Operand_1`, `Operand_2`, `Type_operation`, `Result`.
- Контроллер сохраняет каждый успешный расчёт через `SaveChangesAsync`; не сохраняет некорректный ввод, деление на ноль и бесконечный результат.
- Страница `/Calculator/History` показывает последние 100 записей из базы.
- Начальная миграция `m_init` и снимок модели подготовлены в папке Migrations. При старте контейнера web миграция применяется автоматически через `MigrateAsync`. Это EF-миграция, а не EnsureCreated.
- MariaDB 10.11 (вместо старого образца 10.5 из пособия). Используется `MariaDbServerVersion(10, 11, 0)`.
- Фактический веб-порт 5313, который работал в ПР1; внутренний порт 5055. Внешний порт базы по умолчанию 5043, внутренний 3306. Если преподаватель назначил другой порт базы, измените DB_PORT в .env. В примере пособия для №3 используется 5033; 5043 здесь выбран по схеме 5030 + номер студента, окончательное назначение согласуйте при конфликте.


```bash
chmod 600 .env
sudo docker ps --format 'table {{.Names}}\t{{.Ports}}'
sudo ss -ltn '( sport = :5043 )'
```

## 4. Собрать и запустить

Сначала соберите образ и запустите только базу — работающий калькулятор ПР1 пока можно оставить:

```bash
sudo docker compose build web
sudo docker compose up -d mariadb
sudo docker compose ps
sudo docker images 13-calculator-mariadb
```

У базы ожидается статус healthy (инициализация может занять минуту). Проверить журнал: `sudo docker compose logs --tail=100 mariadb`.

По пособию база может создаваться через HeidiSQL. Здесь контейнер создаёт базу `13-WebCalculatorDb` автоматически через MARIADB_DATABASE при первой инициализации пустого тома. Создавать второй экземпляр базы вручную не требуется. Миграция создаёт таблицу в уже созданной базе.

Перед запуском web найдите, кто занимает 5313:

```bash
sudo docker ps --filter publish=5313 --format 'table {{.ID}}\t{{.Names}}\t{{.Ports}}'
```

Если там ваш прежний контейнер ПР1, остановите его по выведенному имени (`sudo docker stop ИМЯ_ВАШЕГО_КОНТЕЙНЕРА`). Не удаляйте его — можно вернуть запуском docker start, если нужно. Если там уже nizovtsev13-pr2-web, не останавливайте вручную: Compose сам обновит его.

Запустите новый калькулятор:

```bash
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs --tail=100 web
```

Откройте http://93.88.178.186:5313/ . Compose ждёт healthy MariaDB, затем web применяет m_init и запускает HTTP. В журналах ошибка миграции/подключения означает, что приложение ещё не запущено; пришлите текст ошибки, не публикуя пароли. Если .env менялся после создания базы, учтите: MariaDB не меняет уже существующие пароли через environment; верните прежние параметры или измените пароль пользователя SQL-командой, не удаляйте том с данными.

## 6. Миграции в Visual Studio

В комплекте уже есть m_init. **Повторно Add-Migration m_init выполнять не нужно**: это имя уже занято. Автоматическое применение на сервере достаточно для запуска; для демонстрации команды пособия можно выполнить Update-Database из Visual Studio — EF увидит уже применённую миграцию и не создаст таблицу повторно.

Откройте Calculator.csproj, затем Сервис → Диспетчер пакетов NuGet → Консоль диспетчера пакетов. В Default project выберите Calculator. В этой консоли задайте подключение (вместо YOUR_DB_PASSWORD — ваш пароль базы; вместо 5043 — фактический порт):

```powershell
$env:ConnectionStrings__DefaultConnection = 'Server=93.88.178.186;Port=5043;Database=13-WebCalculatorDb;User=calculator13;Password=YOUR_DB_PASSWORD;'
Get-Migration
Update-Database
```

При SSH-туннеле замените сервер на 127.0.0.1 и порт на 15043. Не делайте скриншот команды с реальным паролем. Для запуска локально используйте те же переменные окружения в терминале с `dotnet run`, либо задайте секрет через Visual Studio Manage User Secrets; секрет из консоли диспетчера пакетов не обязательно наследуется запуском F5.

Если преподавателю нужна именно демонстрация создания m_init: ДО первого применения миграции, в отдельной локальной копии проекта удалите только папку Migrations, затем выполните `Add-Migration m_init`. Загрузите созданную EF папку в GitHub и соберите серверный образ заново. Не заменяйте идентификатор начальной миграции после того, как она уже применена: EF посчитает её новой и попытается повторно создать существующую таблицу. Для следующих изменений модели используйте новое имя, например `Add-Migration AddCalculationTime`, затем `Update-Database`.

## 7. Тесты и проверка записей

В браузере выполните четыре расчёта:

| Числа | Действие | Результат | Type_operation в БД |
|---|---|---|---|
| 8 и 2 | + | 10 | Add |
| 8 и 2 | - | 6 | Subtract |
| 8 и 2 | × | 16 | Multiply |
| 8 и 2 | ÷ | 4 | Divide |

Откройте ссылку «История расчётов в MariaDB» на странице. Затем в HeidiSQL откройте вкладку запроса:

```sql
SELECT ID_DataInputVariant, Operand_1, Operand_2, Type_operation, Result
FROM `13-WebCalculatorDb`.`DataInputVariants`
ORDER BY ID_DataInputVariant DESC
LIMIT 20;

SELECT * FROM `13-WebCalculatorDb`.`__EFMigrationsHistory`;
```

Выполните запрос (кнопка запуска / F9). Обновляйте результаты после новых расчётов. Успешное действие добавляет одну строку. В таблице есть исходные числа, тип операции и результат; значения хранятся как varchar(128), как в приложении 3 пособия. При `8 / 0` появляется ошибка и строка не добавляется. Для сравнения количества можно выполнить `SELECT COUNT(*) FROM \`13-WebCalculatorDb\`.\`DataInputVariants\`;` до и после действия.

## Остановка, обновление и сохранность данных

```bash
sudo docker compose stop
sudo docker compose start
```

Для обновления после изменения GitHub:

```bash
git pull
sudo docker compose up -d --build
```

Том базы сохраняется при `docker compose down` и повторном `up`. **Не используйте `docker compose down -v`**: это удалит том и историю расчётов. Не удаляйте том для решения ошибок доступа. В MariaDB root-пароль нужен для администрирования; веб-приложение работает от отдельного пользователя calculator13.
